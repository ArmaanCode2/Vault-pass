How VaultPass protects your vault

Encryption and decryption happen on your own devices. There is no VaultPass server, and your master password never leaves the device you type it on. This page covers both apps, including what they don't do.

This page describes Android 2.7.0, which isn't out yet. The current release, 2.6.x, is different:

  • It has no network access, so no sync and no update check.
  • Screenshot blocking is off until you turn on Disable Screenshots in Settings.
  • Autofill also suggests entries whose title resembles the app's name, so check a suggestion before you tap it.
  • The clipboard is cleared after 30 seconds only while the app is still running.

This page describes Windows 1.1.0, which isn't out yet. The current release, 1.0.1, is different:

  • It checks GitHub for a new version each time it opens (turn this off in Settings, under About) and installs updates without checking a signature.
  • If you turn off Require Master Password on Startup, the saved key stays on disk even after the vault locks, until you turn the setting back on.
  • It can't sync with the current Android release.

Keys and encryption

Your master password becomes a key

Both apps run it through PBKDF2-HMAC-SHA256 with 300,000 rounds and a random salt (16 bytes on Android, 32 on Windows), which gives a 256-bit key. The password itself is never stored, and both apps check it in constant time.

Android vaults created with the older 100,000-round setting are moved to 300,000 rounds the next time you unlock with your master password.

That key unwraps the data key

Your entries are encrypted with a separate random 256-bit data key. The vault stores that data key wrapped, encrypted with AES-256-GCM under the key from your password. Fingerprint unlock on Android and starting without the password on Windows add a second copy; both are described below.

The data key encrypts the entries

AES-256-GCM with a fresh 12-byte IV and a 128-bit authentication tag, so a changed byte makes decryption fail instead of returning altered data.

AndroidEach field (title, username, password, website, notes, category, tags, custom fields) is encrypted separately.

WindowsEach entry is one encrypted record.

What is not encrypted

To list, sort and sync entries, both apps keep a few fields in plain form next to the encrypted data: an internal ID, the favourite and deleted flags, timestamps and, on Windows, the entry type. They never include a title, username, password or website. The names and local IP addresses of paired devices, and on Android the package names of apps you linked for autofill, are stored unencrypted too.

Unlocking and locking

Fingerprint and face (Android)

Off until you turn it on, and only with strong (Class 3) biometrics. Turning it on stores a second wrapped copy of the data key, encrypted by an Android Keystore key that only works after your fingerprint or face is confirmed.

Adding a new fingerprint or face, or removing the screen lock, makes that key unusable; unlock with your master password and turn fingerprint unlock on again. Whether the Keystore key lives in secure hardware depends on your phone.

Starting without the password (Windows)

"Require Master Password on Startup" is on by default. If you turn it off, the data key is kept in a file protected by Windows DPAPI for your Windows account, so any program running as you could read it. From version 1.1.0, every lock deletes that file.

The Windows app has no Windows Hello unlock.

Locking wipes the key

When the vault locks, the data key in memory is overwritten with zeros.

  • Android: locks 1 minute after you leave the app by default. You can pick immediately, 30 seconds, 1, 5 or 15 minutes, or never. While the import or export file picker is open, the vault locks after the auto-lock time or 5 minutes, whichever is longer, so with "Immediately" it can stay open for up to 5 minutes while you choose a file. A file picked after the vault locked is not read or written.
  • Windows: locks after 15 idle minutes by default, and when you lock Windows. Locking on minimise is available but off by default.

Wrong passwords

Android makes you wait 30 seconds after 5 wrong passwords, 60 seconds after 10, 5 minutes after 15 and 15 minutes after 20 or more. The count is kept on disk, so restarting the app or the phone doesn't reset it.

Windows doesn't limit attempts yet. Every guess still costs 300,000 rounds of PBKDF2.

Screen and clipboard

Screenshots

Android blocks screenshots and screen recording of its screens, and shows a blank card in the recent-apps list. From 2.7.0 this is on by default; you can allow screenshots in Settings.

Windows doesn't block screen capture.

Copied passwords

Android marks copies as sensitive, so Android 13 and later hide them in the clipboard preview, and clears the clipboard after 30 seconds. From 2.7.0 this also happens if the app was closed in between.

Windows clears it after 30 seconds by default (10 seconds to never), and keeps copied passwords out of clipboard history and cloud clipboard. Other apps can still read the clipboard while the text is on it.

Sync between devices

Pairing

The Windows app shows a QR code with a one-time 32-byte secret, and the phone scans it. The secret never travels over the network. You approve the phone on the PC, and both keep a pair key that is encrypted with the vault's own key.

Connection

Directly over your local network: TCP port 53853 for the connection, UDP port 53852 for finding each other. Nothing listens unless the Sync screen is open, and it stops when the vault locks. The Windows app can add firewall rules for private networks only, with your administrator approval.

Encryption

Each connection starts with a fresh P-256 key exchange, authenticated with the pair key. After that, every message is encrypted with AES-256-GCM, with separate keys for each direction. A replayed, reordered or altered message ends the connection.

Review before anything changes

The device that starts a sync shows every difference, and you settle each conflict. The other device sees a summary and applies or declines it. Both apply the same plan and compare the result; settings and autofill links never sync.

Backups

Encrypted .vpex files

Both apps write the same format, so a file from one opens in the other. It is encrypted with AES-256-GCM under a key derived from a password you choose (at least 8 characters in both apps; PBKDF2-HMAC-SHA256, 300,000 rounds, random salt; the round count is saved in the file). Backups from older versions, made with 100,000 rounds, still open, but older versions can't open new backups. Imports accept a password of any length, so an older Windows backup made with a 6- or 7-character password still opens. Use a long password for it.

Plain exports

TXT, JSON and (on Windows) CSV exports are not encrypted. Anyone who gets the file can read every password in it. The Windows app also saves .vpb backups, encrypted with the vault's own key.

Downloads and updates

Update checks are off until you turn them on

From Android 2.7.0 and Windows 1.1.0. When you turn them on, each app asks GitHub for its latest release. Nothing from your vault is sent; GitHub sees your IP address, as with any request.

What an update must pass

Android only installs a download that matches GitHub's size and SHA-256 for the file, and refuses a release without a checksum. It must be VaultPass, newer than what you have, and signed with the same key.

Windows 1.1.0 and later also require a VaultPass signature (ECDSA P-256) over the installer, checked against a key built into the app. That is the project's own key, not a Microsoft certificate, so SmartScreen still warns about the installer.

Downloading by hand? Check the file's SHA-256 before you install it.

What it can't protect against

  • Malware or a keylogger on your phone or PC can read what you type and what is on screen while the vault is open.
  • Someone who knows your master password, or who has your unlocked device, can read the vault.
  • A forgotten master password can't be recovered by anyone. Keep an encrypted backup.
  • Plain-text exports and anything left on the clipboard are readable by other apps and people.
  • VaultPass is under active development. Keep your own backups.
